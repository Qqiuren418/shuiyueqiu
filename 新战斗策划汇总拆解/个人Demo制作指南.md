# 核心战斗策划个人 Demo 制作指南

> **目标**：用 UE5 制作一个最小可玩的角色战斗原型 Demo，展示战斗手感调优能力，作为应聘"核心战斗策划（角色向）"岗位的作品集核心交付物。
>
> **核心理念**：Demo 不需要美术资源，白盒 + 基础动画即可，关键是**手感参数可调、可对比**。一个能跑、能调手感、能讲清楚为什么这么调的 Demo，比一份拆解文档更能证明"角色向+手感"这条赛道的能力。
>
> **预期产出**：
> 1. 一个可运行的 UE5 工程（.uproject）
> 2. 一段 3-5 分钟的"调优前 vs 调优后"对比视频，旁白讲解参数差异
> 3. 一份手感参数表（Excel/CSV），记录每个参数的调优过程与决策理由
> 4. 一份 1-2 页的设计说明文档，讲清楚 Demo 的设计意图与手感标准

---

## 0. 总览：Demo 的设计哲学

### 0.1 为什么做 Demo 而不是只做拆解文档

拆解文档证明你"看得懂、想得清"，Demo 证明你"做得出来、调得准"。对于"核心战斗策划（角色向）"这个岗位，**手感是核心交付物**——而手感只能通过可玩 Demo 来证明。一份拆解文档 + 一个可调手感的 Demo，是应聘作品集的"黄金组合"。

### 0.2 Demo 的"最小可行"原则

- **不做美术**：白盒 + 基础 Capsule + Unreal Mannequin 动画即可
- **不做关卡**：一个测试空地 + 一个木桩 Boss + 几个杂兵即可
- **不做剧情**：无叙事，纯战斗沙盒
- **不做完整 UI**：一个参数面板 + 一个风格评级显示即可
- **只做手感**：所有精力集中在"取消链 + 命中停顿 + 反馈层 + 参数面板"

### 0.3 Demo 的"差异化武器"

这个 Demo 要让面试官一眼看到的东西：

1. **参数面板可实时调整**：命中停顿/取消窗口/预输入缓冲可实时调，不需要重启
2. **"调优前 vs 调优后"对比**：录制两版视频，旁白讲改了什么、为什么、效果差异
3. **风格评级系统**：借鉴鬼泣，用评级奖励"多样化连招"——证明你懂表现层驱动
4. **双向躯干值**：借鉴只狼，让防御资源双向流动——证明你懂精准判定驱动

## 1. 第一阶段：环境搭建与基础功能（第 1-2 周）

### 1.1 工程创建（Day 1）

- **引擎版本**：UE 5.3+（LTS 稳定版）
- **模板选择**：Third Person Template（第三人称模板）
- **工程命名**：`CombatPrototype_JobApplication`
- **目录结构**：
  ```
  Content/
    Blueprint/
      Character/      # 玩家角色
      Enemy/          # 木桩 Boss + 杂兵
      GameMode/       # 游戏模式
      UI/             # 参数面板 + 风格评级
    Animation/        # AnimBP + 动画蒙太奇
    Data/             # 参数表 CSV
    Maps/             # 测试关卡
  ```

### 1.2 玩家角色基础（Day 2-5）

- **角色蓝图**：基于 Third Person Character，保留移动/跳跃/相机
- **武器附加**：给 Mannequine 加一个骨骼插槽武器（Cube 模拟剑）
- **攻击蒙太奇**：用 UE5 自带的 Mannequine 攻击动画（或 Mixamo 免费动画），做 4-5 段普攻连段
- **AnimBP**：状态机基础——Idle→Attack1→Attack2→...→Idle，用触发器切换
- **输入映射**：增强输入系统（Enhanced Input），映射"普攻/重击/闪避/格挡/跳跃"

### 1.3 木桩 Boss 与杂兵（Day 6-8）

- **木桩 Boss**：一个 Capsule + 简单受击反馈（闪白 + 硬直 + 受击位移）
- **杂兵**：2-3 个小 Capsule，会缓慢靠近玩家做攻击（用 Behavior Tree 简单 AI）
- **破防条**：给 Boss 加一个"破防值"进度条（UI 显示）
- **受击判定**：武器 hitbox 用 Sphere Collision，在攻击蒙太奇的特定帧开启/关闭

### 1.4 参数面板 UI（Day 9-12）

这是 Demo 的**差异化核心**，必须做出来：

- **参数面板蓝图**：一个 Widget UI，包含可拖动的滑块
- **可调参数**（每个参数一个滑块，范围标注）：
  - 命中停顿帧数（0-20f）
  - 取消窗口开放帧（0-30f）
  - 预输入缓冲帧数（0-10f）
  - 连续格挡最短间隔（0-20f）
  - 命中吸附距离（0-3m）
  - 震屏强度（0-1）
  - 慢动作倍率（0.1-1.0）
- **运行时调参**：用 `Set Timer by Function Name` + `Console Variable`（Cvar）实现运行时调参，不需要重启
- **保存/读取预设**：用 CSV 文件保存参数预设，可加载"调优前"和"调优后"两套预设

### 1.5 阶段一验收标准

- [ ] 玩家角色能移动、跳跃、攻击 4-5 连段
- [ ] 木桩 Boss 能受击、有破防条
- [ ] 参数面板能实时调整 7 个核心参数
- [ ] 调参后游戏内手感立即变化，无需重启

## 2. 第二阶段：战斗系统核心功能（第 3-4 周）

### 2.1 取消链系统（第 3 周，Day 15-19）

这是 Demo 的**手感核心**，参考鬼泣/只狼的取消链设计：

- **取消窗口实现**：在攻击蒙太奇的特定帧设置"取消窗口"通知（Anim Notify），窗口期内可取消进其他动作
- **取消优先级矩阵**：
  - 闪避 > 格挡 > 跳跃 > 下一击普攻 > 重击
  - 用 Enum + Switch 实现优先级判断
- **预输入缓冲**：
  - 玩家输入存入"输入缓冲队列"（Array）
  - 在取消窗口到达时检查队列，触发最高优先级的输入
  - 缓冲窗口可调（参数面板控制）
- **Jump Cancel**：跳跃可从任何动作后摇取消，跳跃后可接空中攻击（可选，时间够再做）

### 2.2 命中停顿与反馈层（第 3 周，Day 20-21）

- **命中停顿**：攻击命中瞬间，用 `Set Global Time Dilatation` 做画面停顿，停顿帧数由参数面板控制
- **震屏**：用 `Client Play Camera Shake`，强度由参数面板控制
- **慢动作**：重击命中时触发 0.3x 慢动作，持续 0.5s，倍率由参数面板控制
- **命中特效**：用 UE5 的 Niagara 粒子做一个简单的"冲击波"特效
- **受击闪白**：用 `Set Material Scalar Parameter` 控制 Boss 受击时材质闪白
- **音效**：用 UE5 自带的音效资源或免费素材，做"金属命中"+"低频冲击"两层音效

### 2.3 格挡与双向躯干值（第 4 周，Day 22-26）

借鉴只狼的"防御即进攻"设计：

- **格挡判定**：按格挡键进入格挡状态，有"完美格挡窗口"（受击前 6-10f，参数可调）
- **完美格挡反馈**：火花特效 + 镜头微震 + 金属"叮"音效
- **双向躯干值**：
  - 玩家与 Boss 都有躯干值（Posture）进度条
  - 完美格挡：累积敌方躯干值 + 少量己方消耗
  - 普通格挡：少量累积敌方 + 大量己方消耗
  - 躯干值满条：触发"忍杀"处决（一个简单动画 + 镜头特写）
- **躯干值恢复**：不受击时缓慢恢复

### 2.4 风格评级系统（第 4 周，Day 27-28）

借鉴鬼泣的"表现层驱动"设计：

- **风格分累积**：每次攻击命中给分，使用不同招式给分更高（防复读）
- **评级显示**：D → C → B → A → S → SS → SSS，右上角 UI 实时显示
- **降级规则**：长时间不攻击或受击降级
- **SSS 高光**：达 SSS 时触发全屏特效 + 主题曲层次加入（可选）

### 2.5 阶段二验收标准

- [ ] 普攻 4-5 连段有取消窗口，可被闪避/格挡/跳跃取消
- [ ] 预输入缓冲工作正常，跨动作缓冲有效
- [ ] 命中时有停顿 + 震屏 + 慢动作 + 特效 + 音效
- [ ] 完美格挡有火花 + 累积敌方躯干值
- [ ] 双向躯干值系统工作，满条触发处决
- [ ] 风格评级系统工作，D 到 SSS 七级显示

## 3. 第三阶段：手感调优与对比视频（第 5-6 周）

### 3.1 调优方法论（第 5 周，Day 29-33）

这是 Demo 的**核心交付物**——证明你"调得准"。

- **调优基准设定**：
  - 先把所有参数设为"明显差"的值（命中停顿 0f、取消窗口 0f、缓冲 0f、吸附 0m）
  - 录制一段"调优前"视频，标记问题点（连段不流畅、命中无反馈、操作无响应）
- **逐参数调优**：
  - **命中停顿**：从 0f 开始，每次 +1f，测到 3-6f，记录"手感开始有重量感"的临界点
  - **取消窗口**：从 0f 开始，每次 +2f，测到 10-16f，记录"连段开始流畅"的临界点
  - **预输入缓冲**：从 0f 开始，每次 +1f，测到 4-6f，记录"操作开始有响应"的临界点
  - **命中吸附**：从 0m 开始，每次 +0.2m，测到 1-1.5m，记录"攻击开始贴身"的临界点
  - **震屏/慢动作**：从 0 开始，每次 +0.1，测到 0.3-0.5，记录"命中开始有冲击感"的临界点
- **交叉验证**：每个参数调好后，关闭其他参数单独测，确认"这个参数单独贡献了什么手感"
- **组合调优**：所有参数调好后，组合测试，记录"组合后的手感是否大于各参数之和"

### 3.2 参数表记录（第 5 周，Day 34-35）

- **参数表格式**（CSV/Excel）：
  ```
  参数名 | 调优前值 | 调优后值 | 调优方法 | 决策理由 | 单独贡献 | 组合贡献
  命中停顿 | 0f | 4f | 每次+1f测到3-6f | 4f时命中开始有重量感 | 命中反馈 | 与震屏组合
  取消窗口 | 0f | 12f | 每次+2f测到10-16f | 12f时连段开始流畅 | 连段流畅 | 与缓冲组合
  ...
  ```
- **每个参数都要有"决策理由"**：不只是"调成 4f"，而是"4f 时命中开始有重量感，3f 偏软，5f 偏拖沓，4f 是临界点"
- **每个参数都要有"反事实分析"**：如果调成 X 会怎样

### 3.3 对比视频录制（第 6 周，Day 36-40）

- **录制工具**：OBS 60fps 固定帧率
- **"调优前"视频**（1-2 分钟）：
  - 所有参数设为"明显差"的值
  - 展示问题：连段不流畅、命中无反馈、操作无响应、格挡无意义
  - 旁白讲解：每个问题对应哪个参数
- **"调优后"视频**（1-2 分钟）：
  - 所有参数设为调优后的值
  - 展示改善：连段流畅、命中反馈强、操作响应灵敏、格挡有意义
  - 旁白讲解：改了哪些参数、为什么、效果差异
- **参数面板演示**（1 分钟）：
  - 录制参数面板实时调参的过程
  - 展示"调一个参数，手感立即变化"
- **总时长**：3-5 分钟，剪辑紧凑，旁白清晰

### 3.4 阶段三验收标准

- [ ] 参数表完整记录 7+ 个参数的调优过程与决策理由
- [ ] "调优前 vs 调优后"对比视频，3-5 分钟，旁白清晰
- [ ] 参数面板实时调参演示视频，1 分钟
- [ ] 每个参数有"调优方法 + 决策理由 + 反事实分析"

## 6. 风险与应对

### 6.1 技术风险

| 风险 | 应对 |
|---|---|
| UE5 蓝图不熟 | 用 C++ 代替部分蓝图；或用蓝图但接受"丑但能跑" |
| AnimBP 状态机复杂 | 从最简状态机开始，逐步加状态，不要一上来做完整状态机 |
| 运行时调参难实现 | 用 Cvar（Console Variable）+ 控制台命令，最简实现 |
| 打包失败 | 用 UE5 官方 Package Project 流程，提前在 Day 30 测试一次 |

### 6.2 时间风险

| 风险 | 应对 |
|---|---|
| 工期超 7 周 | 砍 Jump Cancel + 砍风格评级，保留取消链+格挡+参数面板三件套 |
| 调优卡参数找不到临界点 | 用二分法快速逼近，不要逐帧试 |
| 视频剪辑不熟 | 用 DaVinci Resolve 免费版，简单剪切+旁白录音即可 |

### 6.3 期望管理

| 风险 | 应对 |
|---|---|
| Demo 不够"好看" | Demo 卖的是"手感"不是"美术"，白盒够用 |
| 面试官觉得"不够完整" | 强调这是"手感原型"非"完整 Demo"，设计意图是证明调优能力 |

## 7. 面试时的 Demo 演示话术

### 7.1 30 秒电梯演讲

> "这是我用 UE5 做的角色战斗手感原型 Demo。重点不是美术或关卡，而是这个参数面板——命中停顿、取消窗口、预输入缓冲都可以实时调整。我录了一段'调优前 vs 调优后'的对比视频，旁边是参数表，记录了每个参数的调优过程和决策理由。这个 Demo 证明的是战斗手感的调优能力，不是完整产品。"

### 7.2 5 分钟演示话术

1. **先放对比视频**（2 分钟）：让面试官看到"调优前 vs 调优后"的差异
2. **现场打开参数面板**（1 分钟）：实时调一个参数（如命中停顿从 4f 调到 0f），让面试官看到手感立即变化
3. **讲参数表**（1 分钟）：选 2-3 个参数讲"调优方法 + 决策理由 + 反事实分析"
4. **讲设计意图**（1 分钟）：讲"取消链+双向躯干值+风格评级"三个机制的设计来源（鬼泣/只狼）

### 7.3 常见面试官追问

- **Q：为什么不做完整关卡？**
  - A：因为 Demo 的设计意图是证明手感调优能力，不是完整产品。完整关卡会分散注意力，手感才是岗位核心。
- **Q：为什么用 UE5 不用 Unity？**
  - A：因为目标岗位是 UE5 项目，用 UE5 做 Demo 能直接证明 UE5 协作能力。
- **Q：这个参数面板是策划工具还是玩家工具？**
  - A：是策划调优工具。正式项目中，战斗策划应该有这样的工具来调参，而不是依赖程序改代码。
- **Q：你怎么知道 4f 是最佳值？**
  - A：4f 是调出来的临界点。3f 偏软，5f 偏拖沓，4f 是"命中开始有重量感"的最小值。具体值在不同项目可能不同，但调优方法论可迁移。
