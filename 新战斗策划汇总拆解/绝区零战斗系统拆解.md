## 1. 产品概述

### 1.1 基本信息

- **游戏名称**：绝区零（Zenless Zone Zero / ZZZ）
- **开发商**：米哈游（miHoYo）
- **发行时间**：2024 年 7 月 4 日
- **平台**：PC / iOS / Android / PS5
- **品类定位**：3D 动作 ARPG（多角色切换共斗 + 抽卡养成）
- **商业模式**：免费 + 抽卡

### 1.2 战斗定位一句话

**以三角色切换的"极限支援"为攻防枢纽、以失衡值爆发窗口为节奏核心、以属性异常/紊乱为 Build 深度的二次元动作 ARPG。**

### 1.3 目标用户画像

- **核心受众**：泛动作游戏玩家 + 二次元受众 + 米哈游生态用户
- **操作上下限拉扯策略**：
  - **下限兜底**：金色闪光提示 + 一键连携 + 终结技自动追踪 + 邦布自动技能，给手残玩家"看闪光按键也能过"的路径
  - **上限表达**：极限闪避反击 + 招架支援时机 + 连携顺序优化 + 失衡窗口爆发轴 + 紊乱双异常结算，给硬核玩家"读帧打两倍伤害"的空间
  - **关键矛盾**：闪光提示过于明显，导致硬核玩家"看招拆招"的乐趣被"看闪光按键"稀释——这是绝区零战斗手感的双刃剑

## 2. 角色操作身份分析

### 2.1 角色选择

拆解对象为"三角色小队"整体，而非单一角色——因为绝区零的战斗单位是"队伍"，单个角色的技能组是为队伍循环服务的模块。这是绝区零区别于单角色动作游戏（黑神话、只狼）的核心特征：**战斗差异不在"角色内"，而在"角色间切换关系"**。

### 2.2 核心机制提炼

绝区零的战斗循环同时具备三类特征，主导身份是**状态切换型 + 资源管理型**的复合：

- **状态切换型（主导）**：三角色切换是攻防枢纽。金色闪光→招架支援切人 / 红色闪光→回避支援切人 / 失衡→连携技切人。每一次切换都是状态转换。
- **资源管理型（并行）**：能量（强化特殊技）/ 喧响值（终结技）/ 失衡值（爆发窗口）/ 异常积蓄（属性异常触发）四套资源并行管理。
- **精准判定型（进阶）**：极限闪避反击与招架支援时机是高上限表达，但被闪光提示"补偿"降低了门槛。

**一句话操作身份定义**：

> 三角色小队驱动的状态切换型共斗——靠极限支援切换角色做攻防枢纽，靠失衡值满条做爆发窗口，靠属性异常紊乱做 Build 深度。

### 2.3 角色定位差异化

绝区零用"战斗位置"而非"操作身份"做角色差异化，每个位置承担队伍循环中的不同功能：

| 战斗位置 | 功能定位 | 资源关系 | 代表角色 |
|---|---|---|---|
| 强攻位（主C） | 站场输出，打直伤与失衡 | 消耗能量打强化特殊技 | 妮可、安比 |
| 击破位 | 快速积攒失衡值，破防窗口制造者 | 高失衡倍率招式 | 猫宫又奈、莱卡恩 |
| 异常位 | 积攒属性异常条，触发异常/紊乱 | 异常精通 + 异常掌控 | 蕾米埃尔、简 |
| 支援位/增益位 | 提供增伤 buff，招架/回避支援接续连携 | 强化支援技给主C加成 | 塞斯、丽娜 |
| 防护位 | 承伤 + 受击后快速支援切人 | 高护盾/减伤 | 本 |

**操作身份对比（按战斗位置）**：

| 维度 | 强攻位 | 击破位 | 异常位 | 支援位 |
|---|---|---|---|---|
| 站场时间 | 长（主站场） | 中（破防期） | 中（积攒期） | 短（切入 buff） |
| 核心输出 | 直伤 | 失衡值 | 异常/紊乱 | 增伤 buff |
| 切入时机 | 失衡窗口 | 敌人攻击间隙 | 持续积攒 | 金色/红色闪光 |
| 操作上限 | 连段优化 | 破防时机 | 紊乱双结算 | 招架支援时机 |

## 3. 连段与取消规则拆解（核心章节）

### 3.1 录制与标注方法

- **录制工具**：OBS 60fps 固定帧率
- **逐帧分析**：DaVinci Resolve 帧步进
- **时间戳标注**：MM:SS:FF
- **数据声明**：本节数据为基于录屏反推的近似值，非官方数据，误差 ±2f。绝区零作为服务型游戏，版本更新可能调整参数。

### 3.2 普攻连段帧图（以强攻位 5 连为例）

> 以下为 60fps 录屏反推，非精确解包数据，误差 ±2f。绝区零的普攻连段相对简单，深度主要体现在切换取消而非单角色连段。

| 击数 | 起手前摇 (f) | 活跃判定 (f) | 后摇 (f) | 取消窗口开放 | 可取消进 |
|---|---|---|---|---|---|
| 第 1 击 | ~8f | ~6f | ~16f | 第 10f 起 | 闪避 / 特殊技 / 切人 |
| 第 2 击 | ~8f | ~6f | ~18f | 第 10f 起 | 闪避 / 特殊技 / 切人 |
| 第 3 击 | ~10f | ~8f | ~20f | 第 12f 起 | 闪避 / 特殊技 / 切人 |
| 第 4 击 | ~10f | ~6f | ~22f | 第 12f 起 | 闪避 / 特殊技 / 切人 |
| 第 5 击 | ~14f | ~10f | ~28f | 第 16f 起 | 闪避 / 切人（特殊技需等后摇） |

**关键观察**：

1. **单角色连段深度有限**：普攻 5 连的取消窗口都比较宽（10-16f 开放），单角色内取消链不像鬼泣/黑神话那样做深度。绝区零的深度在"角色间切换取消"而非"角色内连段取消"。
2. **切人取消是核心机制**：任何时候按切人键，当前角色后摇立即被取消，下一角色上场攻击立即触发。这是绝区零手感流畅的根基——也是手残兜底机制。
3. **第 5 击后摇最长（~28f）**：但可被切人取消，因此实战中第 5 击后必切人，不会吃满后摇。
4. **取消优先级**：切人 > 闪避 > 特殊技 > 普攻。切人是最高优先级的"硬取消"。

### 3.3 取消链规则

**取消优先级层级**（高→低）：

1. **切人（极限支援/快速支援）**：最高优先级，可从任何动作后摇中取消。金色闪光期切人触发招架支援，红色闪光期切人触发回避支援。
2. **闪避**：高优先级，可从普攻/特殊技后摇中取消。极限闪避触发子弹时间。
3. **特殊技/强化特殊技**：可从普攻连段中取消（消耗能量），构成"普攻→强化特殊技"的核心连段。
4. **连携技**：仅在敌人失衡时触发，演出期间无敌。
5. **终结技**：喧响值满时触发，演出期间无敌。

**切人取消的核心规则**：

- 切人有冷却（约 2-3s，推测），防止无脑连切
- 切人后下一角色的上场攻击有独立判定，不受前一角色动作影响
- 金色闪光窗口内切人→招架支援（累积大量失衡值 + 打断敌人攻击）
- 红色闪光窗口内切人→回避支援（无敌帧规避 + 触发极限视域）
- 受击飞后切人→快速支援（紧急救场）

**预输入缓冲**：

- **缓冲窗口**：约 5-8f（推测），比黑神话略宽，匹配服务型游戏的受众门槛
- **跨动作缓冲**：存在，普攻后摇期按下闪避/切人，会在可取消帧到达时自动触发
- **闪光提示与输入窗口**：金色闪光出现后约 15-20f 内切人均可触发招架支援，窗口较宽

### 3.4 关键观察与设计推论

1. **取消规则解决了"单角色连段浅 vs 操作流畅"的矛盾**：单角色连段深度有限，但切人取消让三角色轮流上场形成"无限连段"的流畅感。这是用"系统层"解决"角色层"深度不足的设计手法。
2. **闪光提示是双刃剑**：金色/红色闪光让见招拆招变成"看闪光按键"，降低下限门槛但稀释上限乐趣。硬核玩家会抱怨"不用看敌人抬手"，但服务型游戏优先保证大众体验。
3. **切人冷却是平衡阀门**：如果切人无冷却，玩家会无限切人规避所有伤害。冷却强制玩家在"切人保命"和"留切人接招架支援"之间做资源管理。

## 4. 手感参数反推（核心章节）

> 本章所有数值为基于 60fps 录屏反推的近似值，非官方数据，误差 ±2f。

### 4.1 命中停顿

| 攻击类型 | 命中停顿帧数（60fps） | 反推方法 | 误差 |
|---|---|---|---|
| 普攻命中（普通怪） | ~2-3f | 命中瞬间逐帧计数画面静止 | ±1f |
| 普攻命中（Boss） | ~3-4f | 同上，Boss 受击略长 | ±1f |
| 强化特殊技命中 | ~4-6f | 技能命中瞬间计数 | ±1f |
| 连携技命中（每次） | ~6-8f + 镜头特写 | 连携演出期间停顿 | ±2f |
| 终结技命中 | ~10-14f + 慢动作 + 镜头推 | 终结技演出期间 | ±2f |
| 极限闪避反击命中 | ~5-6f + 子弹时间 | 极限闪避后反击命中 | ±1f |
| 招架支援命中 | ~6f + 镜头微推 + 屏震 | 招架支援攻击命中 | ±1f |
| 属性异常触发瞬间 | ~8-10f + 全屏特效 | 异常条满触发瞬间 | ±2f |
| 紊乱触发瞬间 | ~12-14f + 全屏特效 + 慢动作 | 双异常结算瞬间 | ±2f |

**设计推论**：

- 绝区零的命中停顿普遍比黑神话短（普攻 2-3f vs 3-4f），因为服务型游戏追求"爽快节奏"而非"重量感"
- 紊乱触发的停顿最长（12-14f），作为异常 Build 的"高光时刻"奖励反馈
- 连携技/终结技的停顿 + 镜头特写是"演出驱动型手感"——用镜头表现而非动作帧数做重量感

### 4.2 预输入缓冲

| 参数 | 数值（推测） | 反推方法 |
|---|---|---|
| 缓冲窗口 | ~5-8f | 在动作 A 后摇期不同帧按下 B，记录是否触发 |
| 跨动作缓冲 | 存在，较宽 | 普攻第 N 击后摇期按下闪避/切人，自动触发 |
| 切人输入窗口 | 金色闪光后 ~15-20f | 金色闪光出现后不同帧切人，记录是否触发招架支援 |
| 缓冲优先级 | 切人 > 闪避 > 特殊技 | 同时按下切人+闪避，切人优先 |

### 4.3 硬直层级

| 硬直类型 | 触发条件 | 持续帧数（推测） | 恢复规则 |
|---|---|---|---|
| 轻受击 | 普通怪轻攻击命中 | ~15-20f | 可闪避/切人取消 |
| 重受击 | Boss 重攻击命中 | ~30-40f | 可切人取消（快速支援） |
| 击飞硬直 | 击飞类攻击命中 | ~40-60f | 可触发快速支援切人救场 |
| 失衡硬直（玩家方） | 累积受击后 | ~30f | 强制硬直，不可取消 |
| 冻结硬直 | 冰属性异常触发 | ~120-180f | 失衡状态强制 |

**硬直设计特点**：

- 绝区零的硬直普遍可通过切人取消，这是服务型游戏"低惩罚"的设计取向
- 击飞硬直被设计为"切人救场"的触发点，把负面体验转化为正面机制
- Boss 的失衡硬直长达 2-3s（120-180f），是爆发窗口的设计基础

### 4.4 镜头与反馈层

| 反馈类型 | 表现 | 触发条件 |
|---|---|---|
| 震屏 | 普攻弱震 / 特殊技中震 / 连携强震 + 方向感 | 命中时触发，分级 |
| 镜头特写 | 连携技/终结技镜头推近 + 角色定格特写 | 连携/终结技演出 |
| 慢动作 | 终结技命中瞬间 0.2-0.3x 慢放 + 紊乱触发全屏慢放 | 高光时刻 |
| 命中特效 | 核心冲击白光 + 属性层叠特效（火/电/冰/以太） | 命中瞬间触发 |
| 闪光提示 | 金色闪光（可招架）/ 红色闪光（不可招架需回避） | 敌人特定攻击前摇期 |
| 受击闪白 | 角色受击时模型闪白 + 红色边光 | 玩家受击时 |
| 音效配合 | 普攻金属高频 / 特殊技低频冲击 / 连携专属音效 | 按攻击类型分层 |
| 极限视域 | 触发后敌人动作大幅减慢 + 屏幕色调变化 | 极限闪避/回避支援后 |

**设计推论**：

- 绝区零的反馈层是"演出驱动型"——用镜头/特效/慢动作堆叠高光时刻，而非靠帧数据做重量感
- 闪光提示是核心反馈层，把"读敌人动作"转化为"读闪光颜色"，降低门槛但牺牲了硬核读帧乐趣
- 极限视域的"子弹时间"是手感的高光机制，把成功防御转化为视觉奇观

### 4.5 位移与吸附

| 参数 | 数值（推测） | 备注 |
|---|---|---|
| 普攻位移 | 每击前冲 ~0.3-0.8m | 攻击附带微量前移，贴身连段 |
| 特殊技位移 | 部分技能含突进 ~2-4m | 突进类技能有显著位移 |
| 命中吸附 | ~2m 范围吸附 | hitbox 与 target 吸附距离较宽，降低瞄准门槛 |
| 终结技追踪 | 自动追踪 + 位移到目标 | 终结技自动贴脸，无需预瞄 |
| 连携技追踪 | 自动切换到目标位置 | 连携自动贴脸演出 |

**设计推论**：

- 吸附距离比黑神话宽（~2m vs ~1.5m），追踪/自动位移更多——服务型游戏降低操作门槛
- 终结技/连携技自动追踪是"按下就爽"的设计，但减少了玩家的空间决策

## 5. 技能循环与数值

### 5.1 技能组结构

| 技能模块 | 功能定位 | 资源消耗 |
|---|---|---|
| 普通攻击（连段） | 输出 + 能量积攒 | 无 |
| 冲刺攻击 | 位移输出 | 无 |
| 特殊技 | 备用技能（无能量时） | 无 |
| 强化特殊技 | 主力输出技能 | 能量 |
| 闪避 | 防御 + 位移 | 无 |
| 极限闪避反击 | 防御 + 反击 + 子弹时间 | 无（精准判定奖励） |
| 招架支援（切人） | 防御 + 累积失衡 + 切人 | 支援点数 |
| 回避支援（切人） | 防御 + 极限视域 + 切人 | 支援点数 |
| 连携技 | 爆发输出（失衡时触发） | 失衡状态 |
| 终结技 | 终极爆发 | 喧响值（极） |
| 邦布主动技 | 补充输出/控制 | 自动 CD |
| 邦布连携技 | 连携后追加 | 连携触发 |

### 5.2 资源循环

**核心资源**：四套并行

**1. 能量值**：

- 获取：普攻命中 + 受击 + 部分技能回复
- 消耗：强化特殊技
- 循环：普攻积攒→强化特殊技释放

**2. 喧响值**：

- 获取：攻击命中 + 发动特定招式
- 等级：1000/2000/3000 对应"喧"/"特"/"极"三档
- 消耗：终结技（消耗全部喧响值，需达"极"档）
- 注：1.4 版本后各角色喧响值独立计算

**3. 失衡值（敌人方）**：

- 获取：攻击命中累积（不同招式失衡倍率不同）
- 满条触发：敌人进入失衡状态（无法行动 + 承伤增加 + 可触发连携技）
- 持续时间：约 2-3s（Boss）+ 连携次数耗尽后衰减结束

**4. 异常积蓄值（敌人方）**：

- 获取：属性攻击命中累积（5 种属性独立结算）
- 满条触发：对应属性异常状态（灼烧/感电/侵蚀/冻结/强击）
- 紊乱机制：在已触发异常状态下施加另一属性异常，提前结算原异常伤害 + 补偿 + 累积失衡值

**循环节奏**：

```
普攻积攒能量/喧响/失衡/异常 → 敌人攻击闪光提示 → 切人招架/回避支援
    ↓                                          ↓
强化特殊技输出（直伤/异常/失衡）          累积失衡值 + 极限视域
    ↓                                          ↓
    └──────────────失衡满条 ←──────────────────┘
                       ↓
              连携技连锁（2-3 次）+ 邦布连携 + 终结技爆发
                       ↓
                   失衡结束 → 循环重置
```

### 5.3 数值框架

**伤害公式推测**：

```
最终伤害 = 基础攻击 × 技能倍率 × (1 + 暴击伤害) × 失衡易伤倍率 × 属性克制系数 × 减伤系数
```

**失衡易伤倍率**：失衡状态下敌人承伤增加，比例由击破角色的"失衡易伤倍率"决定（如 1.5x/2.0x/2.5x）

**异常伤害公式**（推测）：

```
异常伤害 = 异常基础伤害 × (1 + 异常精通 × 1%) × 属性克制系数 × 失衡易伤倍率
```

**Build 路线分化**：

- 直伤队：堆攻击/暴击/暴伤，靠连携+终结技打爆发
- 异常队：堆异常精通/异常掌控，靠属性异常触发打伤害
- 紊乱队：双属性异常覆盖触发紊乱，提前结算 + 累积失衡值

### 5.4 强度梯度

- T0 Build：紊乱队（双异常结算 + 失衡爆发，上限最高）
- T1 Build：击破位 + 强攻位直伤队（稳定，操作要求中）
- T2 Build：异常单属性队（ buildup 慢，但下限稳定）

## 6. Boss 战与战斗博弈

### 6.1 Boss 行为模式

- **攻击链结构**：Boss 多采用 3-5 击连段套路，含变招
- **闪光提示系统**：每个攻击预登记闪光类型（金色可招架 / 红色不可招架需回避），玩家据此选择应对
- **阶段切换**：Boss 有 2 阶段（血量 50% 触发），部分有 3 阶段。阶段切换伴随新招式 + 新闪光类型组合
- **失衡机制**：Boss 有独立失衡条，满条后进入 2-3s 失衡状态，期间承伤增加 + 可触发 3 次连携

### 6.2 角色 vs Boss 的博弈结构

**核心博弈节点**：

1. **闪光应对博弈**：金色→招架支援切人累积失衡 / 红色→回避支援切人触发极限视域。错误应对（金色招架时机失误 / 红色尝试招架）导致吃伤害
2. **失衡爆发轴博弈**：攒到 Boss 失衡后，连携顺序决定输出效率。低倍率连携先手破盾/攒 buff，高倍率终结技收尾
3. **紊乱时机博弈**：在 Boss 失衡窗口触发紊乱，双异常结算 + 失衡值累积，伤害最大化
4. **切人冷却博弈**：切人 CD 限制，玩家需在"闪光切人保命"和"留切人接招架支援"之间做资源管理

**攻防转换节奏**：

- Boss 攻击期：玩家以闪光应对为主（招架/回避支援切人），寻找反击窗口
- Boss 硬直期：玩家以普攻+强化特殊技输出为主，积攒失衡/异常/喧响
- Boss 失衡期：玩家以连携连锁+终结技+紊乱爆发为主
- Boss 阶段切换：玩家以存好资源/切到合适角色应对新招式为主

### 6.3 难度曲线

- **剧情难度**：闪光提示宽 + 失衡易伤高，手残玩家可过
- **高难本/深渊**：闪光窗口窄 + 失衡易伤低 + Boss 攻击频率提升，要求精准应对
- **挑战模式**：限制终结技/连携使用，强制玩家走异常/紊乱 Build

## 7. 设计意图推论与可借鉴点

### 7.1 设计意图推论

**为什么用"三角色切换"而非"单角色深度连段"？**

- 服务型游戏需要"角色卖卡"——多角色切换让每个角色都是付费点
- 单角色深度连段开发成本高，且服务型游戏受众门槛有限
- 反事实：如果用单角色深度连段，角色差异做不出卖点，且开发成本爆炸

**为什么闪光提示这么明显？**

- 服务型游戏优先保证大众体验，闪光提示让"见招拆招"变成"看颜色按键"
- 降低了硬核读帧门槛，但也稀释了硬核乐趣
- 反事实：如果去掉闪光提示，手残玩家会大量流失，但硬核玩家会更满意——商业上不划算

**为什么切人有冷却？**

- 如果切人无冷却，玩家会无限切人规避所有伤害
- 冷却强制玩家在"切人保命"和"留切人接招架支援"之间做资源管理
- 反事实：如果切人无冷却，战斗会变成"无脑切人"，丧失资源管理深度

**为什么用"失衡值爆发窗口"而非"持续输出"？**

- 失衡窗口创造了"积攒→爆发"的清晰节奏，让玩家有"高光时刻"
- 反事实：如果是持续输出，节奏平淡，且无法体现连携/终结技的演出高光

### 7.2 可借鉴点

1. **三角色切换做攻防枢纽**：把"角色切换"从菜单操作升级为核心战斗机制，每次切人都有攻防价值（招架/回避/连携）。这是服务型动作游戏"卖卡"与"战斗深度"平衡的范本
2. **失衡窗口爆发轴**：用"积攒→爆发"的节奏让玩家有清晰的高光时刻，配合连携/终结演出做视觉峰值。适合任何服务型动作游戏
3. **闪光提示分级**：金色/红色闪光把复杂的敌人动作简化为"颜色-应对"映射，降低门槛的同时保留了"正确应对"的乐趣。但要注意硬核玩家的反馈
4. **紊乱双异常结算**：用"覆盖异常触发提前结算"的机制，给异常 Build 创造高光时刻，且与失衡系统联动。是 Build 深度设计的优秀范例
5. **演出驱动型手感**：用镜头/特效/慢动作堆叠高光时刻，而非靠帧数据做重量感。适合服务型游戏的"大众爽感"定位

### 7.3 可改进点

1. **闪光提示过于明显**：稀释了硬核读帧乐趣，可在高难本中关闭闪光提示或缩短窗口，给硬核玩家专属体验
2. **单角色连段深度不足**：单角色内取消链浅，硬核玩家"角色内"操作上限低。可在高难本加入"单角色连段倍率加成"奖励深度连段
3. **敌人辨识度不足**：群战时敌人攻击缺乏辨识度，玩家容易陷入被群殴的窘境。可加强敌人攻击前摇的视觉差异
4. **切人冷却体验**：冷却期被攻击无法切人，体验割裂。可考虑"受击时切人消耗资源"的应急机制

## 9. 结论与一页纸总结

**核心发现**：

1. **三角色切换是战斗引擎**：绝区零的战斗单位是"队伍"而非"角色"，每次切人都是攻防转换。这是服务型动作游戏"卖卡"与"战斗深度"平衡的核心设计
2. **失衡值爆发窗口是节奏核心**：用"积攒→爆发"的清晰节奏让玩家有高光时刻，配合连携/终结演出做视觉峰值
3. **闪光提示是双刃剑**：降低门槛但稀释硬核乐趣。这是服务型游戏"大众优先"的商业取舍
4. **手感的关键参数决策**：取消窗口宽（10-16f）+ 切人最高优先级 + 命中停顿演出驱动 + 吸附距离宽——共同构成"按下就爽"的下限体验

**对我们项目的 3 条可借鉴启示**：

1. **角色切换做攻防枢纽**：如果项目是多角色 ARPG，把切人从"菜单操作"升级为"攻防机制"。每次切人都有战术价值（招架/回避/连携），而非只是"换个人打"
2. **失衡爆发窗口做节奏**：用"积攒→爆发"的节奏让玩家有清晰的高光时刻，配合演出做视觉峰值。这比"持续输出"的节奏更适合服务型游戏
3. **闪光提示分级要慎用**：闪光提示能降低门槛但会稀释硬核乐趣。建议在高难本中关闭或缩短闪光窗口，给硬核玩家专属体验
