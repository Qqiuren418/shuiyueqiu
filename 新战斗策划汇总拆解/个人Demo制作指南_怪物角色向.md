# 个人 Demo 制作指南（怪物/角色向）

> **岗位定位变化说明**：本指南针对"战斗策划（怪物/角色向）"岗位重新规划。Demo 核心从"角色手感调优"扩展为"Boss设计落地 + 角色设计落地"双交付。面试官要看到的不是"你会调参"，而是"你能从0到1造一个Boss + 造一个角色"。
>
> **核心理念**：Demo 不需要美术资源，白盒 + 基础动画即可，关键是**展示完整的设计落地流程**——设计文档→行为树/技能组原型→反馈层→可玩验收。一个能跑、能展示Boss行为树/阶段切换/攻击辨识度 + 角色技能组/连段/操作身份的 Demo，比任何拆解文档更能证明"怪物/角色设计落地"能力。
>
> **预期产出**：
> 1. 一个可运行的 UE5 工程（.uproject）
> 2. 一个可打的 Boss（三阶段 + 行为树 + 攻击辨识度）
> 3. 一个可玩的角色（技能组 + 连段 + 操作身份）
> 4. 一段 5-8 分钟的演示视频，旁白讲解设计意图与落地过程
> 5. 一份设计文档（Boss设计书 + 角色设计书）

---

## 0. 总览：Demo 的设计哲学

### 0.1 为什么从"手感调优Demo"升级为"怪物/角色设计落地Demo"

纯手感调优Demo证明的是"调得准"，但新岗位核心是"造得出来"。面试官要看到的是：

- **Boss侧**：你能设计一个有阶段切换、有攻击辨识度、有行为树的Boss，并把它落地成可玩内容
- **角色侧**：你能设计一个有操作身份、有技能组、有连段差异的角色，并把它落地成可玩内容
- **落地侧**：你能用UE5的Behavior Tree / GAS / AnimBP 把设计意图转化为可执行逻辑

### 0.2 Demo 的"最小可行"原则

- **不做美术**：白盒 + Capsule + Unreal Mannequin 即可
- **不做关卡**：一个Boss战空地 + 一个角色测试场即可
- **不做剧情**：无叙事，纯战斗沙盒
- **不做完整UI**：Boss血条/阶段指示 + 角色技能CD + 参数面板即可
- **核心精力分配**：60%给Boss设计落地，40%给角色设计落地（怪物向是岗位重心）

### 0.3 Demo 的"差异化武器"

这个 Demo 要让面试官一眼看到的东西：

1. **Boss行为树可视化**：UE5的Behavior Tree可在编辑器可视化，让面试官看到完整的状态节点与转换条件
2. **三阶段Boss**：从阶段1到阶段3的招式解锁+攻击频率提升+辨识度变化，证明你懂阶段设计
3. **攻击辨识度系统**：金色前摇（可弹反）/红色前摇（需闪避）/紫色前摇（不可打断需走位），证明你懂"难但公平"
4. **角色操作身份**：用一句话定义角色（如"取消链型中距离刺客"），并用技能组落地这个身份
5. **设计文档配套**：Demo旁附Boss设计书+角色设计书，证明你能输出规范文档

## 1. 第一阶段：环境搭建与基础功能（第1-2周）

### 1.1 工程创建（Day 1）

- **引擎版本**：UE 5.3+（LTS）
- **模板选择**：Third Person Template
- **工程命名**：`MonsterRolePrototype_JobApplication`
- **目录结构**：
  ```
  Content/
    Blueprint/
      Character/      # 玩家角色
      Monster/        # Boss + 杂兵
      GameMode/
      UI/             # 血条/技能CD/参数面板
      BT/             # Behavior Tree 相关
    Animation/        # AnimBP + 蒙太奇
    Data/             # 设计文档CSV
    Maps/             # Boss战场 + 角色测试场
  ```

### 1.2 玩家角色基础（Day 2-5）

- **角色蓝图**：基于 Third Person Character，保留移动/跳跃/相机
- **武器附加**：Mannequin 骨骼插槽武器（Cube 模拟剑）
- **攻击蒙太奇**：4-5段普攻连段（用UE5自带或Mixamo免费动画）
- **AnimBP**：状态机 Idle→Attack1→...→Idle
- **输入映射**：Enhanced Input，映射"普攻/重击/闪避/格挡/跳跃/技能1/技能2/大招"

### 1.3 Boss基础（Day 6-10）

这是Demo的**怪物向核心**，重点投入：

- **Boss蓝图**：一个大型 Capsule（比玩家大2-3倍，强化Boss感）+ 简单材质（不同阶段换色）
- **Boss动画**：用Mixamo的怪物/巨人动画，或用UE5 Mannequin放大+改动画速度模拟Boss动作
- **Boss血条UI**：顶部大血条 + 阶段指示器（Phase 1/2/3）+ 破防条
- **Boss受击判定**：Body Collision + 阶段性部位受击（头/腿/尾，可选）
- **Boss基础攻击**：3-5种攻击动作（横扫/下砸/突刺/范围AoE/连段）

### 1.4 Behavior Tree 搭建（Day 11-14）

这是Demo的**怪物向技术核心**：

- **Blackboard**：定义Boss的状态变量（当前阶段/目标距离/玩家状态/冷却计时器）
- **Behavior Tree 结构**：
  ```
  Root
    ├─ Selector: 阶段判断
    │   ├─ Phase 1 (血量 100-67%)
    │   │   └─ Sequence: 攻击循环
    │   │       ├─ Wait (观察玩家)
    │   │       ├─ Choose Attack (距离判断)
    │   │       │   ├─ 近距离: 横扫/连段
    │   │       │   ├─ 中距离: 突刺/下砸
    │   │       │   └─ 远距离: 范围AoE
    │   │       └─ Cooldown (攻击间隔)
    │   ├─ Phase 2 (血量 67-33%)
    │   │   └─ Sequence: 新招式解锁 + 频率提升
    │   └─ Phase 3 (血量 33-0%)
    │       └─ Sequence: 终极招式 + 狂暴频率
  ```
- **攻击辨识度实现**：每种攻击在Blackboard里标记前摇类型（金色/红色/紫色），触发对应的视觉提示
- **阶段切换逻辑**：血量阈值触发阶段切换节点，切换时播放演出动画 + 解锁新招式

### 1.5 阶段一验收标准

- [ ] 玩家角色能移动、跳跃、攻击 4-5 连段
- [ ] Boss能移动、有血条、能受击
- [ ] Behavior Tree 可视化结构完整，三阶段切换逻辑工作
- [ ] Boss能根据玩家距离选择不同攻击

## 2. 第二阶段：Boss设计落地（第3-4周）

### 2.1 攻击链与辨识度系统（第3周，Day 15-19）

- **攻击链设计**：每种攻击有完整的前摇→判定→后摇→恢复帧
- **攻击辨识度**：
  - **金色前摇**：攻击前Boss身体闪金光，玩家可弹反（格挡触发完美格挡）
  - **红色前摇**：攻击前Boss身体闪红光，玩家需闪避（不可弹反）
  - **紫色前摇**：攻击前Boss身体闪紫光，玩家需走位（不可打断的持续攻击）
- **变招规则**：同一攻击链可根据玩家行为变招（如横扫→玩家闪避→变招追击下砸）
- **攻击节奏**：每种攻击有不同的前摇时长（30-60f）与惩罚窗口（15-30f）

### 2.2 阶段切换设计（第3周，Day 20-21）

- **阶段1（血量100-67%）**：基础攻击3种 + 攻击间隔2-3s（学习阶段）
- **阶段2（血量67-33%）**：解锁2种新攻击 + 攻击间隔1.5-2s + 变招规则启用
- **阶段3（血量33-0%）**：解锁1种终极攻击（范围大招）+ 攻击间隔1-1.5s + 狂暴模式
- **阶段切换演出**：每次切换播放2-3s的无敌演出动画（镜头特写+全屏特效），给玩家调整时间
- **阶段切换逻辑实现**：在BT里用Decorator判断血量阈值，切换到对应子树

### 2.3 Boss反馈层（第4周，Day 22-26）

- **受击反馈**：Boss受击时材质闪白 + 硬直 + 受击位移
- **破防系统**：Boss有破防条，累积满后进入5s破防状态，期间承伤2x + 可处决
- **处决演出**：破防后玩家按特定键触发处决动画（镜头特写+慢动作+鲜血/能量特效）
- **阶段切换特效**：每次切换全屏特效+震屏+音效
- **攻击特效**：每种攻击有专属特效（横扫有冲击波/下砸有地面裂纹/AoE有能量爆发）
- **音效**：Boss怒吼/攻击命中/阶段切换/破防处决各有独立音效

### 2.4 角色技能组设计落地（第4周，Day 27-28）

这是Demo的**角色向核心**：

- **角色操作身份定义**：一句话定义，如"取消链型中距离刺客"
- **技能组结构**：
  - 普攻 4-5 连段（已有）
  - 重击（蓄力爆发）
  - 闪避（含无敌帧）
  - 格挡（含完美格挡窗口）
  - 技能1（瞬身标记，中距离突进）
  - 技能2（取消链爆发，消耗标记打高伤）
  - 大招（终结技，需资源满）
- **资源系统**：标记数（技能1积攒/技能2消耗）+ 大招能量（攻击命中积攒）
- **操作身份落地**：技能1+技能2的"标记-爆发"循环定义了角色的中距离刺客身份，与"近战贴脸"角色形成差异

### 2.5 阶段二验收标准

- [ ] Boss有5+种攻击，每种有金色/红色/紫色前摇辨识度
- [ ] Boss三阶段切换工作，每阶段有新招式+频率提升
- [ ] Boss有破防条+处决演出
- [ ] 角色有完整技能组（普攻/重击/闪避/格挡/技能1/技能2/大招）
- [ ] 角色的"标记-爆发"循环工作，操作身份可感知

## 3. 第三阶段：联调与演示视频（第5-6周）

### 3.1 Boss vs 角色联调（第5周，Day 29-33）

- **攻防博弈联调**：确保角色的格挡/闪避/技能能与Boss的攻击链形成良好交互
- **难度曲线调优**：
  - 阶段1：攻击间隔宽 + 前摇长，玩家学习辨识度
  - 阶段2：间隔缩短 + 变招启用，要求更快反应
  - 阶段3：间隔极短 + 终极招式，要求完美执行
- **惩罚公平性验证**：每种攻击的前摇是否足够辨识？惩罚窗口是否公平？
- **通关率目标**：设计目标通关率20-30%（熟练玩家可过，手残玩家需多次尝试）

### 3.2 参数面板与文档配套（第5周，Day 34-35）

- **参数面板**：保留之前Demo的参数面板（命中停顿/取消窗口/吸附等），用于现场演示调参能力
- **Boss设计书**（PDF，2-3页）：
  - Boss定位与设计意图
  - 三阶段攻击模式表（阶段/招式/前摇类型/惩罚窗口）
  - 行为树状态机草图
  - 攻击辨识度设计说明
  - 难度曲线分析
- **角色设计书**（PDF，2-3页）：
  - 角色操作身份定义
  - 技能组结构表
  - 资源循环图
  - 与已有角色的差异化说明

### 3.3 演示视频录制（第6周，Day 36-40）

- **录制工具**：OBS 60fps
- **Boss设计演示**（3-4分钟）：
  - 展示三阶段完整Boss战（从阶段1打到阶段3）
  - 旁白讲解：阶段切换逻辑/攻击辨识度设计/行为树结构/难度曲线
  - 重点展示金色/红色/紫色前摇的差异与应对
- **角色设计演示**（2-3分钟）：
  - 展示角色完整技能组与连段
  - 旁白讲解：操作身份定义/标记-爆发循环/与已有角色的差异
- **参数面板演示**（1分钟）：
  - 实时调一个Boss参数（如攻击间隔）+ 一个角色参数（如取消窗口）
- **总时长**：5-8 分钟

### 3.4 阶段三验收标准

- [ ] Boss vs 角色联调完成，攻防博弈流畅
- [ ] 难度曲线合理，通关率目标20-30%
- [ ] Boss设计书 + 角色设计书 PDF 完成
- [ ] 演示视频 5-8 分钟，旁白清晰

## 6. 风险与应对

### 6.1 技术风险

| 风险 | 应对 |
|---|---|
| UE5 Behavior Tree 不熟 | 从最简BT开始（2节点），逐步加阶段与变招 |
| AnimBP 状态机复杂 | Boss用简单状态机（Idle/Attack/受击/阶段切换），不要一上来做完整 |
| Boss动画资源难找 | 用Mannequin放大+改动画速度模拟Boss动作，或用Mixamo巨人动画 |
| 打包失败 | 提前在Day 30测试一次Package Project流程 |

### 6.2 时间风险

| 风险 | 应对 |
|---|---|
| 工期超7周 | 砍角色技能组深度（保留普攻+1技能+大招），保留Boss三阶段+辨识度三件套 |
| Boss难度调不准 | 用二分法逼近目标通关率，不要逐帧试 |
| 设计书写不熟 | 参考《竞品拆解文档大纲模板》的结构，套用即可 |

### 6.3 期望管理

| 风险 | 应对 |
|---|---|
| Demo不够"好看" | Demo卖的是"设计落地能力"不是"美术"，白盒Boss+白盒角色够用 |
| 面试官觉得"不够完整" | 强调这是"设计落地原型"，核心是展示从0到1的Boss+角色设计流程 |

## 7. 面试时的 Demo 演示话术

### 7.1 30秒电梯演讲

> "这是我用UE5做的怪物/角色设计落地原型Demo。左边是一个三阶段Boss，有完整的Behavior Tree行为树、金色红色紫色三色攻击辨识度、阶段切换演出与破防处决。右边是一个可玩角色，有完整的技能组与标记-爆发操作身份。配套有Boss设计书和角色设计书。这个Demo证明的是从0到1的设计落地能力。"

### 7.2 5分钟演示话术

1. **先放Boss战演示视频**（3分钟）：从阶段1打到阶段3，旁白讲解阶段切换/辨识度/行为树
2. **现场打开BT编辑器**（1分钟）：展示Behavior Tree可视化结构，讲状态节点与转换条件
3. **展示角色技能组**（1分钟）：打一套完整连段，讲操作身份与标记-爆发循环

### 7.3 常见面试官追问

- **Q：为什么Boss分三阶段而不是两阶段？**
  - A：三阶段创造了"学习→进阶→终极"的节奏曲线。两阶段太短，四阶段太拖。三阶段是动作游戏Boss设计的甜点区。
- **Q：金色红色紫色三色辨识度会不会太简单？**
  - A：三色是基础层，进阶可以加前摇时长差异/音效差异/动作差异。Demo用三色做最小可行，正式项目会多层叠加。
- **Q：行为树为什么不用状态机？**
  - A：行为树更适合"多条件触发+优先级选择"的Boss AI，状态机更适合"线性状态转换"。Boss行为复杂度高，BT更合适。
- **Q：角色的标记-爆发循环会不会太单一？**
  - A：这是Demo的最小可行版本，正式角色会加更多变招与资源管理。核心是展示"操作身份定义→技能组落地"的设计方法。
